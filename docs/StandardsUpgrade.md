## 1. Procedure and its deviation from the plan

The plan named `scripts/validate-path.sh` per standards file, or
`scripts/validate.sh dev_only`. Neither reaches Verus for a standards file:

1. `validate-path.sh` verifies `path/lib.rs`, a parallel build regenerated by
   `scripts/regenerate-path.sh` from veracity `.vp` files. It takes no file
   argument, and `path/` does not exist in this checkout.
2. `dev_only` is not a feature in `src/lib.rs` or `Cargo.toml`, so
   `validate.sh dev_only` is a full-crate run.
3. A full-crate run stops in rustc type checking (273 errors after agent 1,
   `logs/validate.20260920-151314.log`) before Verus starts. No standards
   file is ever verified by that route until the chapter files type-check.
4. `src/lib.rs` sets `verifier::deprecated_postcondition_mut_ref_style(true)`
   while vstd 09.13 writes its own `ensures` with `final(self)`, so a bare
   standards file handed to `verus` without that crate attribute is judged
   under the wrong `&mut` postcondition style.

I therefore wrote a throwaway driver in the session scratchpad
(`verify-standard.sh`) that builds a harness crate root carrying the six
`src/lib.rs` crate attributes, declares `pub mod standards { #[path = ...]
pub mod <name>; }` (the same path a `$crate::standards::...` macro expects),
optionally declares the dependency set for the four standards that import
crate modules (`Types`, `Concurrency`, `ParaPairs`,
`Chap02::HFSchedulerMtEph`, `vstdplus::{accept, clone_view, feq,
total_order, threads_plus}`), optionally declares a scratchpad copy of a
PTT's test bodies as `pub mod ptt;`, acquires a slot through
`scripts/verus-lock.sh`, and runs `verus --crate-type=lib <root>
--multiple-errors 20 --expand-errors --num-threads 8` with the same ANSI
strip and `tee` as `validate.sh`. Every run wrote
`logs/validate-standard-<name>.<timestamp>.log`; every log was read. Runs
were sequential; each took 0 to 1 s because vstd is precompiled. The
dependency set alone verifies at 179 verified, 0 errors
(`validate-standard-BASELINE.20260920-152719.log`, 4 deprecation warnings
from `src/Types.rs:82,83,105,106`), so a dependent standard's own count is
its total minus 179.

The driver is a session artifact, not a product script; section 6 asks
whether `validate.sh` should gain a per-file mode.

### 2.3 `wrapping_iterators_standard.rs`

Decision, with evidence: wrapping another collection's iterator no longer
needs a wrapper type. The rewritten standard shows two patterns on
`InnerS` (Vec-backed) and `OuterS` (wraps `InnerS`):

- Pattern A, re-expose (the default): `OuterS::iter()` returns exactly the
  `std::slice::Iter` that `InnerS::iter()` returns and restates the triple
  over `OuterS`'s own view. No new type, no new spec, no proof obligation.
  This is the "chained" variant of 15 of the 71 APAS iterators.
- Pattern B, adaptor by delegation, for a module that must own its iterator
  type: `OuterIter { inner: std::slice::Iter }` forwards `next()` and
  implements `IteratorSpecImpl` with `remaining`, `will_return_none`,
  `decrease` and `peek` forwarding to the inner iterator's (as vstd's own
  `impl IteratorSpecImpl for &mut I`, `std_specs/iter.rs:424`), and
  `obeys_prophetic_iter_laws` written as the inner value, the constant
  `true`. It verifies, with the same cost as A plus one O(1) forwarding call.

## 5. The 09.13 iterator standard

Two styles, and a rule for wrapping:

- Delegated (68 of 71 APAS iterators): a Vec-backed collection returns the
  std iterator vstd already specifies. `iter()` returns
  `std::slice::Iter<'_, T>`; `IntoIterator for &Self` returns the same;
  `IntoIterator for Self` returns `std::vec::IntoIter<T>`. No iterator
  struct, no iterator `View`, no ghost iterator, no `iter_invariant`, no
  hand-written `next` contract.
- Custom (the three lazy AVLTreeSeq iterators): a struct with private fields
  and a `#[verifier::type_invariant]`, a closed `elts()` for the stable
  creation-time contents, `impl Iterator` with a plain `next` (no `ensures`;
  the contract is vstd's, checked against the spec impl), and
  `impl IteratorSpecImpl` with exactly five spec fns:
  `obeys_prophetic_iter_laws` (`true` for a verified iterator),
  `remaining` (`#[verifier::prophetic]`, the items still to be returned),
  `will_return_none` (`#[verifier::prophetic]`, `true` when it terminates),
  `decrease` (`Some(non-prophetic metric)`), `peek(index)`
  (`Some(elts()[index])` in range). Optional:
  `ExactSizeIteratorSpecImpl::exact_len`, `DoubleEndedIteratorSpecImpl::peek_back`.
  `initial_value_relation` no longer exists.
- Wrapping: re-expose the inner collection's iterator (same type, triple
  restated over the outer view). An adaptor that forwards is written only
  when the module must own its iterator type, with `obeys` as the inner
  value written out.

Constructor postconditions, the guide's triple, on every `iter()`,
`into_iter()` and custom constructor:

    IteratorSpec::remaining(&it) == self@.as_ref(),          // prophetic sequence
    vstd::std_specs::slice::into_iter_elts(it) == self@,     // what peek reads
    IteratorSpec::decrease(&it) is Some,                     // for-loop termination

For a consuming iterator: `self@` without `.as_ref()` and
`vstd::std_specs::vec::into_iter_elts`. For a custom type the middle clause
is `IteratorSpec::remaining(&it) == it.elts()`. When the constructor is a
trait method returning a same-crate iterator type, clauses 1 and 3 name the
inner std iterator (`&it.inner`), not the returned type (section 2.3,
behaviour 2). A custom constructor carries
`#[verifier::when_used_as_spec(<open spec form>)]` so that
`for x in it: ctor(..)` has a spec value.

Loop-invariant idioms. A `for` loop names its wrapper and reasons through
`it.index()` (items consumed), the prophetic `it.seq()` (the whole sequence)
and `it.history()` (items consumed so far):

    for x in it: coll.iter()
        invariant
            it.seq() == orig.as_ref(),
            collected.len() == it.index(),
            forall|i: int| 0 <= i < collected.len()
                ==> #[trigger] collected@[i] == *it.seq()[i],
    { collected.push(*x); }
    assert(collected@ =~= orig);   // it.index() == it.seq().len() after the loop

A manual loop wraps the iterator in `VerusForLoopWrapper::new(it)` and adds
`it.wf()`, `IteratorSpec::obeys_prophetic_iter_laws(&it.iter)` and
`IteratorSpec::decrease(&it.iter) is Some` to the invariant; `it.next()`
returns `Option<Item>` and maintains `wf()`.

The `decreases` rule: `it.seq()` is prophetic and may not appear in
`decreases`. A manual loop measures the iterator's non-prophetic
`IteratorSpec::decrease(&it.iter)->0`, and draws its conclusion before
`break`, because the prophetic equality does not survive the break. `it` is
not in scope after a `for` loop; post-loop facts come from the iterator's
`when_used_as_spec` form.

PTT patterns (six): `loop-borrow-iter`, `loop-borrow-into`,
`for-borrow-iter`, `for-borrow-into`, `loop-consume`, `for-consume`; a
custom iterator adds `for-custom` and `loop-custom`. Templates:

## 6. The finite-sets rule as rewritten

At 09.13 `vstd::set::Set<A>` is finite by construction: `Set::finite()` is
`open spec fn finite(self) -> bool { true }`, `#[deprecated]`
(`vstd/set.rs:227`); the possibly-infinite type is `vstd::iset::ISet<A>`.
`src/standards/finite_sets_standard.rs` now states four rules:

1. Never write `.finite()` on a `Set` or on a `Map::dom()`. It is a
   deprecation warning and carries no information; as a wf conjunct it is
   `true` in disguise, which `spec_wf_standard.rs` forbids. A wf states real
   invariants only. vstd removed `axiom_set_*_finite`,
   `lemma_set_subset_finite`, `lemma_set_union_finite_iff` and
   `seq_to_set_is_finite`; a proof statement that called one established a
   tautology and is deleted, not replaced (agent 1 deleted 24 such
   statements).
2. `Set::new(f)` returns `Option<Set<A>>` (`vstd/set.rs:133`): a
   comprehension over a bare predicate is a `Set` only if the predicate's
   extension is finite, which vstd cannot decide from `f`. A spec fn typed
   `Set<A>` cannot return it and a `Set<A>` cannot be compared to it with
   `==` (agent 1's root cause 1, 81 sites).
3. Preferred: comprehend inside a finite set with `filter`. `s.filter(f)` is
   a `Set<A>` whenever `s` is, and `lemma_set_filter` (`group_set_lemmas`)
   gives `s.filter(f).contains(a) <==> s.contains(a) && f(a)`. Every APAS
   comprehension `{x in A | p(x)}` names an enclosing finite set, the
   collection's own view, so it is written `self@.filter(p)`. The standard's
   `spec_evens(s) = s.filter(|x| x % 2 == 0)` and `lemma_evens_contains` show
   this needs no proof steps.
4. Otherwise the `lemma_set_new_some` route: show `ISet::new(f).finite()`
   (with `lemma_iset_finite_if_subset_of_seq`, `vstd/iset.rs:1006`, or
   `lemma_iset_subset_finite` against `s.to_iset()`, which
   `lemma_to_iset_finite` makes finite), then `lemma_set_new_some(f)` gives
   `Set::new(f) is Some` and `lemma_set_new(f, a)` gives membership; both are
   in `group_set_lemmas`. Bind the predicate to a named spec fn
   (`spec_lt(bound)`) so the spec and the proof name one closure term. The
   standard's `lemma_below_is_some(bound)` proves `Set::new(spec_lt(bound))
   is Some` and its membership this way.

The example `FiniteCollection` (a `Vec<u64>` viewed as `Set<u64>`) now has
the real invariant `elements@.no_duplicates()` as its wf, a verified linear
`contains`, an `insert` that ensures `self@ == old(self)@.insert(x)` through
`Seq::to_set_ensures` and `lemma_push_to_set_commute`, and a `len` that
ensures `count == self@.len()` through `unique_seq_to_set`. The module's
`broadcast use` must be one braced statement
(`broadcast use { group_set_lemmas, group_iset_lemmas };`): Verus allows one
module-level `broadcast use`.
